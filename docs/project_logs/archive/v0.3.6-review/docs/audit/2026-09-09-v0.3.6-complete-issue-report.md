## 4. 数值计算问题

### N-01 幂运算优先级和结合方向错误 — S0

- **位置**：`lib/models/math.dart:361-385, 421-446`。
- **反例**：计算 `2*x^2`，令 `x=3`；数学结果应为 `2*(3²)=18`。
- **实测**：返回 36，相当于先算 `2*x`，再对整体平方，即 `(2*3)²`。
- **原因**：预处理把 `^` 转为 `**`，但解析器把幂与乘除放在同一个从左到右的循环中。幂应高于乘除，而且通常按右结合处理。
- **改进**：拆分 `parsePower` 层，让 `parseMulDiv` 只消费乘除；幂采用右递归；解析结束后检查是否仍有未消费字符。增加 `2*x^2`、`2^3^2`、`-x^2`、括号和科学计数法回归。

### N-02 显示舍入污染内部数据 — S0

- **位置**：`lib/models/exec.dart:363-366, 430-447, 483, 496-506, 559-576, 674-693, 717-823, 1034-1095`。
- **反例**：显式函数 `0.0000001*x`，在 `x=1` 应为 `0.0000001`。
- **实测**：内部曲线点为 0。
- **原因**：执行层反复使用 `toStringAsFixed(4/5/6)` 后再 `double.parse`，把显示精度写回计算数据。小量被归零，后续积分、拟合和交点继续使用这个错误值。
- **改进**：内部全程保留 `double`；只在标签、属性面板和导出文本的最后一步格式化。需要可控量化时，应由用户显式选择精度和舍入模式。

### N-03 非均匀网格中心差分公式错误 — S0

- **位置**：`lib/models/math.dart:47-70`。
- **反例**：`x=[0,1,3]`，`y=x²=[0,1,9]`，在 `x=1` 的准确导数是 2。
- **实测**：返回跨点割线斜率 `(9-0)/(3-0)=3`。
- **原因**：代码使用只在等距网格上可作为中心差分近似的跨点斜率；非均匀间距需要由三点插值多项式推导权重。
- **改进**：实现非均匀三点差分公式，端点使用相应单边公式；先检查 X 严格单调。教学推导和反例见 `docs/learning/08-尺度不变性与异步快照反例.md`。

### N-04 重复横坐标被伪造为极小间距 — S1

- **位置**：`lib/models/math.dart:47-70`。
- **反例**：两点 `(1,1)`、`(1,2)` 的横坐标相同，不能定义普通的 `dy/dx`。
- **实测**：函数没有报错，而是返回数值输出。
- **原因**：零分母被静默替换为 `1e-9`。这不是测量误差模型，只是把未定义运算伪装成很陡的有限斜率。
- **改进**：要求 X 严格递增或先提供明确的聚合策略；发现重复或逆序立即返回带行号的错误。不得用任意 epsilon 改写用户数据。

### N-05 线性求解不具备尺度不变性 — S0

- **位置**：`lib/models/math.dart:89-114`。
- **反例**：`diag(1e-20,1e-20)x=[1e-20,2e-20]`；整体缩放不改变解，仍应为 `[1,2]`。
- **实测**：返回 `[0,0]`。
- **原因**：用固定绝对阈值 `1e-12` 判断主元是否为零。所有系数都小于阈值时，可逆矩阵被误判并跳过求解。
- **改进**：使用带缩放的部分主元选取和相对容差，例如结合矩阵范数、机器精度与维度；返回秩和条件信息。更稳妥的拟合应使用 QR 或 SVD。

### N-06 奇异系统被返回为普通解 — S0

- **位置**：`lib/models/math.dart:89-114`，多项式拟合调用点 `117-138`。
- **反例**：`[[1,1],[2,2]]x=[2,4]` 秩不足，没有唯一解。
- **实测**：返回 `[2,0]`，没有任何警告。
- **原因**：小主元直接跳过，未求得的分量保留初始零值。调用者无法区分唯一解、无穷多解和失败。
- **改进**：对秩不足明确返回结构化错误；API 返回解、秩、残差、条件估计。多项式拟合不要构造正规方程，因为 `AᵀA` 会平方条件数。

### N-07 z-score 在大有限数上溢出 — S0

- **位置**：`lib/models/exec.dart:557-576`。
- **反例**：`[1e200,2e200]` 的均值为 `1.5e200`，总体标准差为 `0.5e200`，结果应为 `[-1,1]`。
- **实测**：得到 `[-0,0]`。
- **原因**：直接累计平方偏差，`(5e199)²` 超过 `double` 范围成为无穷大，标准差也成为无穷大。
- **改进**：使用稳定的在线方差算法（Welford）或先按最大绝对偏差缩放；明确总体/样本标准差语义；对非有限中间量报错。

### N-08 min-max 的极差计算溢出 — S0

- **位置**：`lib/models/exec.dart:557-576`。
- **反例**：`[-1e308,1e308]` 应映射到 `[0,1]`。
- **实测**：得到 `[0,NaN]`。
- **原因**：`max-min` 溢出为无穷大，正端计算中出现 `∞/∞`。
- **改进**：先按安全尺度平移和缩放，或使用分段比例；对常量列、极值列和非有限输入分别处理，保证有限输入不会静默产生 NaN。

## 5. 数据导入、缺失值和表格语义

### D-01 分类列使 `dropMissing` 删除所有行 — S0

- **位置**：`lib/models/exec.dart:512-520`。
- **反例**：表格含 `group=[control,treated]` 和 `response=[1,2]`，没有缺失值；执行删除缺失行。
- **实测**：输出为空表。
- **原因**：代码把“无法转成数字”当作“缺失”。所有合法文本分类值都被判为 null，于是每行都被删除。
- **改进**：缺失判定应基于原始 null、空字符串或用户配置的缺失标记；数值转换失败只能用于数值列类型验证。给列建立明确类型和缺失掩码。

### D-02 合法的多行 CSV 字段被拆坏 — S0

- **位置**：`lib/models/csv.dart:13-52`，核心行为在先调用 `.split('\n')`。
- **反例**：两条记录，第一条字符串字段为合法的 quoted multiline 值 `"A\nB"`，数值为 1；第二条为 `C,2`。
- **实测**：样本列变为 `A`、`B,1`、`C`，数值列变为 `null,null,2`。
- **原因**：解析器在理解引号状态之前先按物理换行切记录。RFC 风格 CSV 的引号字段可以包含换行。
- **改进**：使用状态机逐字符解析，只有在引号外才结束记录；正确处理 `""` 转义、CRLF、BOM 和末尾空字段。优先采用成熟 CSV 库并用规范语料回归。

### D-03 无表头文件静默丢失第一条观测 — S1

- **位置**：`lib/models/csv.dart:61-69`。
- **反例**：无表头数据 `A,1\nB,2`。
- **实测**：只保留 `B,2`；`A,1` 被当作列名。
- **原因**：启发式表头判断对混合文本/数值行不可靠，且导入界面没有让用户确认。
- **改进**：提供“有表头 / 无表头 / 自动检测”三种明确模式；自动模式展示预览和置信提示，不能在无提示的情况下删除数据行。

### D-04 稀疏 XLSX 的列宽变化导致崩溃 — S1

- **位置**：`lib/models/csv.dart:152-208`，越界访问约在 `198` 行。
- **反例**：第一行仅 A1 有值，第二行 C2 出现数值 2.5。
- **实测**：抛出 `RangeError`。
- **原因**：每一行按读取当时的最大宽度保存；发现后续更右的单元格后全局列数变大，但旧行没有补齐，随后用新宽度索引旧行。
- **改进**：先扫描 worksheet 的使用范围再分配矩形矩阵，或在最大列数增长时补齐已有行；加入首行稀疏、合并单元格、空 sheet 和公式单元格测试。

### D-05 缺失点被删掉并跨缺口连线 — S0

- **位置**：`lib/models/exec.dart:1063-1115`，绘制行为随后消费该曲线。
- **反例**：`x=[0,1,2]`、`y=[0,null,2]`。科研折线应保留三点位置并在中间产生断线。
- **实测**：只输出 `(0,0)` 与 `(2,2)` 两点，绘图会把它们直接连接。
- **原因**：转换节点跳过所有不可转数值的行，没有保存缺失掩码或 NaN 分段标记。
- **改进**：以 NaN/segment ID 表示断点；绘制器遇到非有限点结束当前 path。另提供用户显式选择的插值、删除或断线策略。

### 额外确认的数据层问题

#### D-06 不等长列可能越界崩溃 — S1

`table_to_scatter` 用两列的最大长度循环，却直接索引两列；`table_to_series` 按 X 长度索引 Y；清洗节点又按第一列行数索引全部列。位置包括 `lib/models/exec.dart:512-520, 1027-1030, 1088-1090`。不规则表格可触发 `RangeError`。应在 `DataTable` 边界建立矩形不变量，或所有消费者使用安全访问和显式缺失值。

#### D-07 `.xls` 扩展名与实际解析器不匹配 — S1

导入入口接受 `.xlsx` 和 `.xls`，实现实际按 ZIP/OOXML 结构处理，只适用于 XLSX。传统二进制 XLS 会失败。应移除虚假支持声明或引入真实 BIFF 解析器，并在 UI 中显示具体支持版本。

#### D-08 损坏 UTF-8 被静默替换 — S2

`lib/models/csv.dart:232,252` 使用 `allowMalformed`。损坏字节会变成替换字符，分类标签和样本 ID 可无提示改变。应默认严格解码，并允许用户明确选择编码或确认替换预览。

## 6. 函数、几何和绘图保真度

### G-01 `1/x` 的间断点被虚构为普通点和交点 — S0

- **位置**：`lib/models/exec.dart:403-452` 及曲线相交 `835-947`。
- **反例**：在 `[-1,1]` 上以 3 个样本绘制 `1/x`，再与 `y=0` 求交。数学上没有交点。
- **实测**：得到伪交点 `(0,0)`。
- **原因**：非有限函数值被跳过而没有插入断段标记；内部舍入又可能把极小值变成 0。剩余有限点被当作连续折线连接，几何算法便在不存在的线段上求交。
- **改进**：函数采样保留 segment 边界；检测非有限值、定义域错误和极大跳跃；自适应细分；交点算法只能处理同一连续段内的相邻点。

### G-02 长曲线第 3000 段之后的交点被漏掉 — S1

- **位置**：`lib/models/exec.dart:835-947`，输入在 `849-850` 行被 `sublist(0,3000)` 截断。
- **反例**：两条 3001 点曲线只在最后一段 `x=2999.5` 相交。
- **实测**：返回零个交点。
- **原因**：为限制复杂度直接丢弃第 3000 个点之后的数据，没有告警，也没有抽样误差说明。
- **改进**：用包围盒、空间索引或 sweep-line 降低候选段数量；若设置上限，必须返回“结果不完整”的状态，不能静默截断。

### G-03 微小但有效的坐标范围被改成单位范围 — S0

- **位置**：`lib/ui/viewer.dart` 中 `_mapV` 和轴范围/tick 计算，约 `120, 218, 719, 878, 2438` 行。
- **反例**：用户明确设置 Y 轴 `[0,1e-12]`。
- **实测**：最大值被扩成 1。
- **原因**：使用固定绝对下限 `1e-9` 或默认 `1` 防除零，把“范围很小”和“范围为零”混为一谈。
- **改进**：仅在端点相等或非有限时扩展；扩展量相对于中心值和机器精度计算。显示刻度使用科学计数法，不改变数据范围。

### G-04 标准散点图静默丢弃第 5001 点 — S1

- **位置**：`lib/ui/viewer.dart:778-787`。
- **反例**：输入 5001 个散点。
- **实测**：只绘制前 5000 个。
- **原因**：固定 cap 被直接应用到数据序列，没有抽样、聚合或可见提示。
- **改进**：优先采用批量绘制、LOD 或与像素分辨率相关的保形抽样；若仍限制，界面和导出必须显示“已降采样”及原始/显示点数。

### G-05 原则散点图静默丢弃第 6001 点 — S1

- **位置**：`lib/ui/viewer.dart` 的 principled scatter 绘制分支，点数上限为 6000。
- **反例**：输入 6001 个点。
- **实测**：只绘制 6000 个。
- **原因与改进**：同 G-04。两套绘图路径上限不同，还会让同一数据在不同节点中得到不一致图形，应统一数据降采样策略和元数据。

### G-06 数值 X 被当作等距类别 — S0

- **位置**：`lib/ui/viewer.dart:924` 起的 `_paintLineFromTable`。
- **反例**：X 为 `[0,1,10]`、Y 为 `[0,1,2]`。第二点的水平归一化位置应为 `(1-0)/(10-0)=0.1`。
- **实测**：第二点位于 0.5，三个点等距排列。
- **原因**：表格折线用行索引分配水平位置，没有按数值 X 映射。
- **改进**：列类型为 numeric/time 时按数值坐标映射；只有分类轴才等距。轴标签、命中测试和导出应共享同一 transform。

### 额外确认的图形和统计语义问题

#### G-07 主图与叠加图元各自独立拟合坐标 — S0

`lib/ui/viewer.dart:667,2367` 的 overlay 绘制会重新根据 overlay 自身坐标拟合范围。反例是主图 X 范围 `[0,10]`，叠加点 X=10；该点应与主图右端对齐，但独立拟合会按 overlay 的单点默认范围放置。叠加层必须接收主图已经确定的 world-to-screen transform，不能再次自动定界。

#### G-08 热图、箱线图、小提琴图静默截列/截行 — S1

`lib/ui/viewer.dart:1250,1255,1400,1507` 分别限制热图最多 10 个数值列/120 行、箱线图 12 列、小提琴图 8 列。超出部分没有可靠的“未显示”状态。应提供分页、选择器、聚合或显式错误，并让导出记录选取范围。

#### G-09 箱线图须明确须线定义与异常值 — S2

当前箱线图以最小值/最大值作须，没有常见的 `1.5×IQR` 须和离群点标记。它不一定数学错误，但图形语义可能与读者默认理解不同。应提供 Tukey、min-max、percentile 三种模式，并把定义写入图注/元数据。

#### G-10 小提琴图带宽缺少可解释选择 — S2

核密度带宽为硬编码启发式，并带固定绝对下限。不同尺度和样本量下会过平滑或产生尖峰。应使用尺度相对的 Silverman/Scott/交叉验证选项，显示带宽，并支持同尺度组间比较。

#### G-11 火山图显著性语义过于固定 — S2

显著点阈值采用固定 `|log2FC|>1`、`p<0.05`，没有清楚区分原始 p 值与多重检验校正后的 q/FDR。应让阈值和列语义可配置，并在图例或图注显示。

#### G-12 README 声明色带节点，注册表中无对应可创建节点 — S2

`README.md` 的节点清单提到 Colorbar，数据模型和 viewer 仍保留旧色带输入处理，但 `lib/models/registry.dart` 没有 `colorbar_input` 注册配置。用户无法从正常节点库创建这一能力。应恢复注册和 UI，或删除文档声明并迁移遗留图。

## 7. 工作流、执行引擎和可复现性

### W-01 保存工作流不能复现随机输入 — S0

- **位置**：`lib/store/graph_store.dart:1010-1017`；随机采样还使用 `math.Random()`，见 `lib/models/exec.dart` 约 `644` 行。
- **反例**：创建随机火山图预设，保存 JSON，再加载同一文件。
- **实测**：标签仍相同，但所有随机数值列发生变化。
- **原因**：工作流只保存节点、边、组和参数，没有保存已实现的数据、随机 seed 或生成器状态。
- **改进**：每个随机节点必须有持久化 seed；工作流保存算法版本、seed、输入文件哈希和关键参数。若要冻结结果，另存数据快照并校验哈希。

### W-02 排队任务用旧快照覆盖新状态 — S0

- **位置**：`lib/store/graph_store.dart:1333-1382`，尤其是排队前捕获 `final prev = results`，再于 `1379` 附近串行执行。
- **反例**：初始 `a=1,b=10`；快速把 a 改为 2，再把 b 改为 20；等待执行链稳定。
- **实测**：最终为 `a=1,b=20`，a 的新结果被旧快照覆盖。
- **原因**：第二个任务入队时捕获的 results 仍是第一次任务完成前的旧对象。虽然任务串行执行，快照却不是在真正开始时读取。
- **改进**：任务开始执行时读取上一任务已提交结果；引入单调 revision，旧 revision 禁止提交；合并待执行 dirty set。增加独立分支交错修改、同节点连改和结构变更回归。

### 额外确认的执行层问题

#### W-03 建立连接可能触发两次执行 — S1

`GraphStore.onConnect` 在 `lib/store/graph_store.dart:904-934` 已调用 `runAfterGraphChange`；`lib/ui/node_canvas.dart:1097-1124` 的 `_finishConnect` 随后又在 auto-run 下调用 `runPipeline()`。同一次连接可重复做全图计算，并扩大 W-02 的竞态窗口。执行触发权应只归 store；UI 只发动作。

#### W-04 Isolate 失败后无提示退回 UI 主线程 — S2

`lib/store/graph_store.dart:1366-1375` 捕获所有 isolate 异常后同步执行。大图或大数据会从“后台失败”变成“界面卡死”，而真实错误被隐藏。应只捕获已知的可序列化错误，记录原因，并向 UI 返回降级状态；重计算仍应在 worker 中完成。

#### W-05 非多输入端口可接多条边，结果取决于边顺序 — S1

连接入口没有验证端口占用；`lib/models/exec_engine.dart:196-220` 对非 multi 输入反复赋值，最后一条边覆盖前值。同一逻辑图仅因边数组顺序不同就可能得出不同结果。应在建边时拒绝，或以明确的“替换已有连接”事务处理。

#### W-06 加载图缺少结构和数值验证 — S1

`lib/store/graph_store.dart:1020` 起只做很弱的 JSON 外形检查，没有充分验证版本、重复节点 ID、未知类型、悬空边、端口兼容性、非有限坐标和循环。损坏或恶意工作流可能到执行期才崩溃或产生部分结果。应定义 schema、迁移版本和原子加载校验。

#### W-07 有环图仍按备用顺序尝试执行 — S1

拓扑排序失败后执行引擎退回 node ID/原序列继续运行，而不是把循环作为图级错误终止。结果会依赖节点排列和残留结果。应先检测并展示最小循环路径，整次运行原子失败。

#### W-08 缺少取消、进度、资源预算和任务合并 — S2

高采样函数、大表格和复杂几何可能创建无界列表或长任务。用户缺少取消和阶段进度，快速编辑还会堆积过期任务。应使用可取消 token、节点级预算、分块处理、debounce/coalescing，并让过期 revision 尽早退出。

## 8. 科研绘图关键能力缺失

以下不全是“代码错误”，但会阻止“能够执行所有科研绘图所需功能”这一目标成立。

| 能力缺口 | 位置/审查结果 | 原因与影响 | 等级 | 改进方案 |
| --- | --- | --- | --- | --- |
| SVG/PDF 矢量导出 | README 和导出实现只提供 PNG；未找到 SVG/PDF 后端 | 导出架构围绕位图快照，放大、排版和期刊印刷质量不足 | S1 | 增加 SVG/PDF 后端，文本保留为矢量或可嵌入字体 |
| 物理尺寸、DPI、字体嵌入 | 导出界面没有 mm/inch、DPI、字体嵌入或 PNG `pHYs` 配置 | 只设置像素尺寸，无法稳定满足期刊物理尺寸和印刷分辨率 | S1 | 同时指定画布物理尺寸、DPI、字体与色彩空间，并写入元数据 |
| 误差条、置信区间、拟合区间 | `lib/models/registry.dart` 未注册 error bar/CI ribbon 节点，拟合输出也无区间 | 数据模型只覆盖点线和系数表，无法表达测量与参数不确定度 | S1 | 增加对称/非对称 error bar、CI ribbon 与统计来源元数据 |
| 对数、log-log、symlog、时间轴 | axis 注册和 viewer transform 只有线性数值映射 | 缺少 scale 抽象，大跨度、带符号对数和时间数据不能按标准方式展示 | S1 | 把 scale 作为坐标轴一级对象，统一 transform、tick 与反变换 |

| 数据/工作流 provenance | 保存结构仅含节点、边、组和参数 | 缺少输入哈希、节点算法版本和环境信息，无法追踪图的来源 | S1 | 保存输入哈希、节点版本、软件版本、时间、seed 和环境摘要 |
| 权重、残差、条件数、参数不确定度 | `lib/models/math.dart:117-138` 和拟合节点主要输出曲线/系数 | 算法 API 没有诊断对象，用户无法判断病态、异方差和参数可信度 | S1 | 输出 residual、R²/适用指标、协方差/CI、秩和条件估计 |

## 10. 为什么作者的 88 项测试仍会全部通过

作者测试证明主路径和当前实现约定内部一致，但测试集合没有覆盖这些反例类别：

1. 极小/极大尺度和尺度不变性；
2. 奇异、病态和不等距数值问题；
3. CSV 引号内换行、无表头和稀疏 XLSX；
4. 缺失值的统计语义与折线断段；
5. 长数据尾部、绘图 cap 和非均匀 X 映射；
6. 保存后的随机可复现性；
7. 排队异步任务之间的确定性交错。

测试通过率只能回答“已写断言是否通过”，不能自动证明断言覆盖了科研正确性。今后的测试应以不变量组织：缩放不改变线性系统解、有限输入不应产生非有限输出、保存重载应复现、坐标变换应一致、完整解析应守恒记录数。
