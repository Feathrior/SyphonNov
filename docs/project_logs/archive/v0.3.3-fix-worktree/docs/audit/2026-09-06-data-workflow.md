## 实测结论

独立诊断文件为 `examples/audit/data_workflow_probe.dart`，运行方式：

```powershell
flutter test examples/audit/data_workflow_probe.dart --no-pub --reporter expanded
```

四项检查的实际结果为 **1 通过、3 失败，退出码 1**。它们断言科研工作流应有的行为，失败用于暴露未解决问题；文件放在 `examples/audit/`，不会混入默认 `test/` 回归套件，也没有用“错误仍存在”来增加绿色测试数。完整输出见 [诊断日志](../verification/audit-data-workflow.txt)。

| 编号 | 输入与所需行为 | 实际结果 | 影响与证据 |
| --- | --- | --- | --- |
| DATA-01 | 两行表格的 sample 列为 `A\nB`、`C`，value 为 1、2；CSV 导出后再读入应保持两行及列配对 | sample 变成 `A`、`B,1`、`C` 三行，数值列变为 null、null、2 | 引号内换行被当成记录换行，损坏观测配对。`lib/models/csv.dart:12` 先拆行，`splitLine` 的引号状态仅在单行内维持；`csvCell` 却能导出合法多行字段 |
| DATA-02 | XLSX 第一行只写 A1 列名，下一行在 C2 有数值；空表头应补名或给明确校验错误 | `RangeError`，发生在 `lib/models/csv.dart:190` | 按读取时的宽度分配早期行，最后按更大的全局列数索引旧行，未补齐；常见稀疏工作表不能可靠导入 |
| DATA-03 | 保存含随机预设的工作流，再加载，应能重建作图时的数据或明确说明只保存了生成规则 | 同一 JSON 加载后随机数值变化 | `saveGraph` 只保存节点参数和结构，不保存已生成的数据；`loadGraph` 会重新运行预设。见 `lib/store/graph_store.dart:999`、`:1114`，`lib/models/sample_data.dart:10` |
| 对照 | 手动 CSV 数据 `x,y / 0,1 / 1,2` 保存与加载 | 数值完整保留 | 说明工作流保存并非一概失效；导入文本写入 dataText 参数的路径能够随 JSON 保存 |

DATA-03 与第一轮已修问题不同：第一轮保证改页面或样式不重算上游；本轮检查的是**关闭/重新加载工作流**。固定“抽样节点”的 seed 也不能固定其上游“示例数据生成器”的输入。

## 能力清单

| 项目 | 状态 | 源码依据和范围 |
| --- | --- | --- |
| CSV/TSV、粘贴、文件拖入 | 部分支持 | `lib/models/csv.dart`、`lib/main.dart:152`；简单有表头数据可用，DATA-01 未通过；只有分隔符选项，缺少表头、字段类型、编码的明确导入配置 |
| XLSX | 部分支持 | `xlsxBytesToColumns` 只取第一个工作表；没有选表、日期样式解析和公式重算；DATA-02 未通过。已缓存公式值可被读取，不等于存在 Excel 计算引擎 |
| 旧 `.xls` | 实际不支持 | 文件入口接受扩展名，但送入 ZIP/OOXML 解码器；错误文字也说明仅支持 `.xlsx`，见 `csv.dart:234` |
| 工作流 JSON 保存/加载与撤销 | 已有，复现保证有限 | `graph_store.dart:999`；嵌入的手动数据可保存，随机预设实际值不保存；载入检查格式标记与 nodes，但没有严格验证版本、节点 ID 唯一性和完整数据模式 |
| 原数据来源与运行清单 | 缺失 | 保存格式没有原文件摘要、软件版本、运行时间、已实现随机状态、输入/输出内容校验等运行清单；UI 日志只保存在内存且最多 200 条（`graph_store.dart:1274`） |
| 批量/无界面运行和批量导图 | 未提供产品入口 | `lib/main.dart:23` 是桌面窗口入口，无 CLI 参数；导出依赖交互式保存对话框。内部函数可被测试调用不等于面向用户的批处理接口 |
| 长任务取消与大数据性能 | 未建立保证 | `runPipeline` 同步调用 `runGraph`；每个节点遍历连线、计算在当前执行链完成。未见后台隔离执行、取消、分块导入或性能门槛测试；没有跑海量数据基准，因此不写成某个规模必定卡顿 |
| 科学数据格式与外部分析扩展 | 未提供专门入口 | 未发现 HDF5/NetCDF/Parquet 或 Python/R 插件协议；这些属于领域和规模扩展，不能仅凭缺少其中一种就判整个工具不合格 |

## 优先级

DATA-01、DATA-02 应在扩大图表种类前修正：数据读错或读不进会影响所有后续算法。DATA-03 应通过保存实现后的数据快照，或可版本化的生成器及其随机状态解决；同时明确“保存工作流”与“保存这次实验”的差别。

批量入口、运行清单、后台执行适合在核心正确性稳定后补。领域格式按实际研究数据选择，不建议把所有格式一次塞进项目。
