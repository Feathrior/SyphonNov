# 窄面板与数据预览滚动修复

日期：2026-09-05。来源：整套测试的 `mini_table_test.dart` 和 `widget_test.dart` 失败。

## UI-01：未选择节点时，属性面板在小高度下溢出

空状态的标题、说明与五类节点帮助原来放在不可滚动的 Column 内。应用默认测试尺寸下，可用内容高度只有 288 px，内容溢出底部 23 px；实际缩小窗口同样会截断帮助。

修复把完整帮助内容放入可滚动容器，保留原排版与内边距。没有放大测试窗口、裁掉文字或忽略异常。

验证保留应用原尺寸启动测试，并新增 300 × 160 px 的属性面板：拖动后最后一项帮助必须落入可视区域，且无布局异常。

## UI-02：MiniTable 的滚动条依赖运行平台，缺少明确的双轴控制

原组件依赖 Flutter 的自动桌面滚动条，在其他默认平台并不提供可拖动滚动条；原测试还在寻找已经移除的自定义 GestureDetector，因此 `find.last` 直接报错。仅改查找器会让“能拖动滚动条”的要求失去验证。

现在表格为横纵两轴各持有一个 ScrollController，显式使用 Flutter RawScrollbar；自动滚动条在这个局部被关闭，避免重复。两根滚动条均围绕同一个可视区域绘制，横向滚动条不会落在纵向表格内容的最末端。组件卸载时释放控制器。

更新测试在 240 × 120 px 的可视区域里放入横纵都超出的数据，实际拖动两根滑块前进、到达末端后回拖，并检查对应的滚动位置变化。测试也验证两个轴相互独立、滚动条位于同一可视区域及卸载无异常。

## 验证结果

`mini_table_test.dart` 和 `widget_test.dart` 合并运行 **3/3 通过**。相关四个文件完成格式化及定向静态分析。最终整套结果由主任务在所有并行改动完成后统一记录。
