# 测试覆盖、数据语义与实验复现

本篇来自第二轮能力审计。前一轮 111 项回归测试通过，本轮仍用很小的输入找到了新的失败。理解这两件事为什么不矛盾，比继续增加一个测试数量更重要。

先修：[表达式与误差传播](01-表达式与误差传播.md)。本篇不修改数值算法，关注数值计算前后的数据对象是否保持相同。

## 1. 测试通过的量词范围

设程序应满足性质 $P(x)$，已测试输入集合为 $T$，所有合法输入集合为 $X$。通过这些测试至多提供

$$\forall x\in T,\quad P(x)$$

的执行证据，并不能仅凭 $T\subseteq X$ 推出

$$\forall x\in X,\quad P(x).$$

当 $X$ 很大甚至无穷时，有限样例不能直接变成全称证明。解析推导、接口条件、性质测试和边界输入可以共同增强证据，但都要明确自己的范围。因而“111 项全过”和“一个新反例失败”可以同时成立：后者不在前者实际覆盖的输入中。

本轮把独立诊断放在 `examples/audit/`，明确保留失败状态。它们是未解决问题的证据，不是新增功能的通过证明。具体输出见 [数据工作流审计](../audit/2026-09-06-data-workflow.md)。

## 2. 用往返不变量检验数据没有被悄悄改写

令 $E$ 为导出，$D$ 为导入。在格式能够表示原数据的前提下，理想性质是

$$D(E(A))=A.$$

这里相等包括：行数、列数、列名、字段内容、空值位置和观测配对。对本例中的整数和文本，可以用精确相等；不需要浮点容差。不同文件格式可能不能保留全部字段类型，此时应事先声明可保留的结构，而不是暗中把别的对象当成原对象。

实际表格为：

| sample | value |
| --- | ---: |
| A 后跟一个字段内换行，再跟 B | 1 |
| C | 2 |

合法 CSV 可以把含换行的字段放在双引号内。项目导出器确实这样做，但导入器先把文本按换行拆开，再对每一行单独解析引号。它失去了跨行的“当前是否在引号内部”状态，于是重新读成三行，1 也进入了文本 `B,1`，对应数值位置变为空。

这是**数据结构与语义错误**，不是浮点舍入。即使后面的 QR 和差分完全正确，也只能针对被损坏的数据求解。正确解析需要跨越整个输入维持状态：仅当当前不在引号字段内，换行才结束一条记录；转义的双引号也要单独处理。此次是审计记录，该解析修复尚未实施。

## 3. 保存参数为什么不等于保存实验

把一条科研流水线写成

$$Y=F(D,\theta,s,v),$$

其中 $D$ 是具体输入数据，$\theta$ 是处理与绘图参数，$s$ 表示随机状态，$v$ 表示程序和运行时版本。保存节点结构和参数仅保存了其中一部分。

例如，示例数据由随机生成器产生，保存文件只记了“使用火山图预设”。重新打开时生成器产生了新的 $D'$，即使 $\theta$ 完全相同，也通常有

$$F(D',\theta,s,v)\ne F(D,\theta,s,v).$$

第一轮给抽样节点固定 seed，仅保证同一个输入上的抽样可复现；如果抽样前的数据已经变了，相同行号也会选到不同观测。第一轮还阻止改页面时重算数据，但这不自动覆盖关闭后重新打开工作流的行为。

本轮实测：手动输入 CSV 的保存/加载保持数据不变；随机预设的保存/加载改变了数据。因此不能写成“保存功能全部坏了”，也不能写成“保存 JSON 已保证实验复现”。改进可以保存实际数据快照；若选择保存生成规则，还应保存可重建的随机状态与实现版本。严谨研究通常也应记录原始数据来源和内容摘要。

## 4. 为数值程序选择新的验证输入

与其只增加同一类正常数据，优先按语义条件扩展：

- 文本字段含逗号、引号或换行时，观测配对是否保持？
- 行列不齐或表头缺失时，是否补齐或明确拒绝？
- 只改显示单位时，物理关系是否保持？
- 保存后重开时，数据、参数和生成状态是否保持？
- 函数有间断点时，采样点之间是否仍可合法连线？

这把输入处理、计算与可视化连接起来，避免只验证算法中心的一小段。

## 自测

**A.** 已经对 100 个整数验证了 $f(n)>0$，是否证明对所有实数 $x$ 都有 $f(x)>0$？给出一个反例函数。

<details><summary>答案</summary>

不能。若测试的是 $n=1,\ldots,100$，取 $f(x)=x-1/2$，这些整数上都为正，但 $x=0$ 时为负。甚至将结论只推广到所有整数，也需要额外论证。

</details>

**B.** 本篇两行表格中的一个字段含换行。文件有更多物理文本行，能否据此说观测条数也增加了？

<details><summary>答案</summary>

不能。字段内换行属于一个字段的内容，观测仍为两条。物理换行和记录分隔符只有在正确语法状态下才相同。

</details>

**C.** 先随机生成 200 个观测，再以 seed=0 抽取 20 个。为什么仅固定第二步 seed 不够？

<details><summary>答案</summary>

第二步固定的是行索引的选择；第一步的具体观测仍可能变化。需要保存生成后的数据，或同时固定并记录第一步可复现的生成状态及版本。

</details>

## 附录：两个已经复现、尚未修复的数值反例

本轮 [计算与统计审计](../audit/2026-09-06-numerical-statistical.md) 还提供了两个与前文紧密相关的反例。原始输出见 [数值诊断记录](../audit/2026-09-06-numerical-probe.txt)。这里只记录待修问题，不表示本轮已经修改了算法。

**1. 对象丢失：`1/x` 被连成了另一条曲线。** 在 `x=-1,0,1` 上采样，程序跳过 x=0 的无穷结果，只留下 `(-1,-1)` 和 `(1,1)`。随后曲线求交把二者连成直线，于是在 y=0 上报告 `(0,0)`。但 `1/x` 没有零点，x=0 也不属于它的定义域。介值定理要求区间上的连续性，不能只看端点异号。这里需要保留分段与定义域信息；丢掉未定义点并不等于消除了间断。

**2. 中间溢出：有限数据得到错误的零标准分数。** 总体式 z-score 为 `z=(x−μ)/σ`。`[1,2]` 得到 `[-1,1]`；把两个数都乘 `1e200` 后，本应不变，当前却得到 `[-0,0]`。此时均值 `1.5e200` 和标准差 `5e199` 都能表示，但直接求差的平方约 `2.5e399` 已超出 double 范围，导致标准差变成 Infinity。这与“最终答案太大”不同，也不能只靠 Kahan 求和修复，因为错误在相加以前就已发生。

自问：把 `1/x` 的采样点增加十倍，就能证明跨过 x=0 的连线合法吗？

<details><summary>答案</summary>

不能。增加采样密度只改变近似折线；它没有补上 x=0 的定义，也没有证明函数在该点连续。无论采样点是否恰好落在零点上，连接两侧分支都需要独立的定义域/分段判断。

</details>
